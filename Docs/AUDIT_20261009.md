**GEPREK! audit and repair — 9 October 2026**

Changes were made to the existing project. Unity 6000.5.9f1, URP 17.6.0, Input System 1.20.0, the art, recipe data, scene layout, and build configuration were preserved. This is a targeted repair and polish pass, not a claim that every possible gameplay state is bug-free.

**Architecture and audit coverage**

The intended build entry is `Assets/_Project/Scenes/Main.unity`, the sole enabled build scene. SampleScene and the URP template are not build entries. Main contains Camera, EventSystem, Locations, Player, Managers, and UI roots. Locations switch between Warung, Ruko, Restaurant, and Home in one scene. The builder scripts author the scene/prefabs; no full rebuild was run.

GameManager controls menu → story/tutorial → briefing → operating/closing → report → home → sleep → arc evaluation. GameEvents connects UI, economy, staff and progression. ScriptableObject data contains 8 recipes, 11 items, 7 upgrades, 9 customer types, and 3 arcs of 5 days. Customer/Staff/Player prefabs use code-driven CharacterAnimator sprite poses rather than AnimatorController assets. Player movement uses a continuous Rigidbody2D; customer/staff movement follows scripted routes. NPC trigger colliders intentionally do not block the player. World renderers use Default sorting with Y-based orders and explicit overlays; the overlay Canvas uses order 10000.

The cooking chain is raw chicken → fryer → prep → plating components → customer. Customers request dishes; employees cook, deliver, or operate the cashier. Employees do not have a separate personal food-request system. The shared customer request presentation was improved for both player and staff gameplay.

Inspected the principal runtime systems, builders, UI construction, scene references, dependencies, build settings, progression/save logic, staff routes and audio source pool. Runtime serialized-reference traversal included inactive locations: 631 MonoBehaviours at the inspected moment, no missing scripts or dangling serialized object references. All eight recipe icon references are valid; their sprite bounds are approximately 1.10–1.13 by 0.83–0.86 world units. Existing import settings/materials/physics layers were retained. This was not an exhaustive GPU or texture-memory profiling session.

**Issues by severity and implemented fixes**

| Severity | Finding | Result |
|---|---|---|
| High | Escape closed the pause panel while leaving time stopped | Closing the pause modal resumes GameManager; modal closure follows visible sibling order |
| High | Recipe book stopped the player while orders/cooking kept ticking | Opening during a shift pauses; closing resumes; opening from Pause stays paused |

| High | Mid-shift saves restored earned money but restarted the day's customers | Save the shift-opening progress checkpoint; report this behavior in the pause UI |
| High | Cook could wait forever after player emptied a claimed fryer | Detect missing/empty fryer and bounded timeout, release claims and recover |
| Medium | Stale cooking, carried food, and staff jobs crossed shifts | Reset active business kitchen, staff jobs/claims/routes and player carry at opening |
| Medium | Customers could continue changing state after day accounting | Clear remaining customers before finalizing report; suspend cooking outside shifts |
| Medium | Queue entry overwrote the first route waypoint with its destination | Follow the supplied route in order |
| Medium | Negative purchase values awarded money; addition could overflow | Reject negative spending, saturate balance using wide arithmetic, report actual delta |
| Medium | Virtual movement/interaction could remain held across freeze/disable | Reset virtual input, clear pending press, track joystick pointer ownership |
| Visual | Food sprites too small; missing sprite became invisible | World dish scale ×1.85, bubble background ×1.35, separated mood/meter, visible '?' fallback |
| Visual | Request lacked a large named display | Selected-customer card with 100×100 reference-unit aspect-preserved food image, dish name, waiting/urgent/ready text and 0.18s reveal |

| Usability | New card could overlap carry slot | Card replaces carry slot only while inspecting a waiting customer; decorative graphics do not block pointer input |
| Usability | Save-error toast was parented beneath hidden menu HUD | Toast is now on the screen root and remains visible above menus |
| Performance | Objective text rebuilt every frame; staff name strings regenerated every frame | Objectives refresh at 5Hz; staff labels update when name/status changes |

**Intentionally preserved / limits**

Story, art identity, Indonesian copy, 8 recipe mappings, economy tuning, customer personalities, location geometry, animation system, input package, render pipeline and Unity version remain intact. Existing pooled audio voices and feedback effects were retained; no sound pack or extra screen shake was added. Listening tests were not possible, so audio balance is not certified. No invasive navigation replacement, scene regeneration, or speculative object pooling was warranted.

Active shifts resume from their opening checkpoint, including pre-consumption promotion state, because live world state is not serialized. Completed shifts retain earnings and resume at home. Older saves without the new flags cannot reliably reveal whether an ordinary saved day had already finished; they retain the existing briefing behavior, while day-past-arc saves route to evaluation. Backup recovery is tested on this macOS Editor; WebGL/mobile file-system behavior and a standalone build were not tested.

The UI remains landscape-oriented. Portrait, notched-device safe areas, every upgrade combination, all cutscenes, prolonged sessions, audio balance, and a complete 15-day campaign need manual verification. No claim is made that every path through every furniture arrangement has been exhaustively collision-tested.

**Play Mode checklist**

1. Open `Assets/_Project/Scenes/Main.unity`. Press Play; verify title buttons, confirmation before overwriting a save, opening story, tutorial and briefing.
2. Use WASD/arrows and the on-screen joystick. Walk around every counter/table and into room boundaries. Check acceleration, stop, facing and animation; verify touch drag ends when menus open.
3. Let a customer sit and order. Face/approach them empty-handed: see the enlarged bubble and large named card. Inspect Original, Sambal Merah and later toppings; verify each sprite matches its label. Walk away and confirm the carry slot returns.
4. Prepare raw chicken → fry → lift when ready → hold E/Space at prep → plate with requested components → deliver. Verify only one payment and correct money. Test too-early pickup, burnt food, wrong order and trash.
5. Open the recipe book during cooking: time/patience should pause. Close to resume. Open it from Pause: closing should leave Pause active. Press Escape once to resume; confirm movement/hold input is released.
6. In Ruko/Restaurant, observe cook/server/cashier. Take a cook's ready chicken yourself: the cook should abandon the empty fryer and resume useful work. Check busy queues and movement between stations.
7. Save during a shift and Continue: restart at that shift's opening checkpoint. Complete a shift, save at the report/home, and Continue: return home with earnings preserved. Sleep once; verify empty stations and no old staff jobs. Test arc evaluation and final story continuation.
8. Switch Game View to 1024×768, 1280×720, 1920×1080 and 2560×1080. Check title, HUD, order card, recipe book, shop, pause, report, dialogue and branches for overlap/clipping; scroll long lists.
9. Listen on speakers/headphones for clipping/repetitive alerts and compare music/SFX/ambience. Test actual touch devices and application focus loss.
10. Run the full campaign and a target-platform build before release; inspect the Console for game-code exceptions. Run Edit Mode tests while stopped, and wait for scene restoration before entering Play Mode.
